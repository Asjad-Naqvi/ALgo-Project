## Campaign acceptance

- Day 1 starts at HQ, location 0, with normal inputs and targets target_0. Day 2 uses wave 0 and target_1, rounds each road time up after multiplying by 1.5, doubles tool-crate values and adds a priority-9 alarm at tick 0.
- Day 3 uses wave 1 and target_2 and doubles food values. Day 4 uses wave 2 and target_0 and doubles location penalties of at least 2. Day 5 uses wave 3 and target_1, triples medicine values and adds a priority-10 alarm at tick 0.
- Day 6 uses the union of all waves and target_2. Day 7 keeps the union and makes a one-way evacuation to target_0 with no truck loading.
- Apply wave indices modulo the number of waves. Build daily inputs from base values, round values down after multiplication and skip unreachable trips. Load only on Days 1–6 when the trip goes ahead. A window is unavailable when (window_id + day) is divisible by 5. Release one available alarm per tick and drain the queue.
- Run A/B/C/D together, add F on the reachable component, and show daily inputs, decisions, constraints, outcomes and baseline differences for at least five master cases including an L case and a trap. Use greedy A, Bellman–Ford B, scan D and Prim F on the same daily inputs. For weighted C, use the proposal's exhaustive baseline within its feasible range and report DNF beyond it. Any scalable supplementary heuristic and any added E compression baseline go in the proposal-change notes.
- Test all four master traps (46–49) in their relevant modules. Case 47 inventory is a candidate for the required difficult scenario. Show the measured gap and explain the exact solver's capacity-dependent limitation.

## Experiment and submission checks

- Use the released master CSVs for scored runs. If they are unavailable, continue implementation and unit tests with small fixtures and hold official measurements and campaign evidence until the release arrives. Record the version, checksum, seed, sampled IDs and pooling rules. Sample each tier at master-order positions 1, 8, 15 and so on, using zero-based positions for seed 1. Pool according to the brief and generate seeded connected graphs for larger network sizes.
- Test every module on at least five geometric sizes with identical inputs for primary and baseline. Where a large exact comparison is infeasible, retain the capped attempt as DNF and record the largest completed size and missing-point prediction. Use single-thread timing excluding data loading, one discarded warm-up, five measured runs, median and IQR. Record memory beyond input where feasible, family-specific operation counts and preprocessing separately.
- Keep one row per run in `results/results.csv` with module, experiment, algorithm, instance, size, size2, time_s, time_iqr_s, ops, mem_bytes, status and note. Record hardware and software, label plots with units and algorithm names, and report the fit slope or exponential base, 95% CI, R² and relative prediction error. Explain poor fits, measured surprises and failures.
- Keep separate verification code with normal, boundary, malformed and trap cases, Tier S claims or small exact references, and output invariants. Record the original failure for each deliberate mutation and rerun after restoring the correct implementation.
- Deliver README with one master-data run command and module recommendations backed by measured evidence, with assumptions, reversal conditions, monitoring measurements and a ranked list of three engine failure modes. Include prediction log, master metadata, Iteration 1 files, proposal, proposal-change notes, repository link, source, tests, results/plots/sample outputs and final report. Use the verified roll-number and section pattern for the ZIP. Check submission instructions for the required private repository name before changing the current GitHub name.

## Git workflow

Start each day from current `main`, work on a branch such as `ali/day-2-inventory`, and stage only the files you own. Commit and push from your own account, open a PR, and have a teammate review and merge it using a method that preserves the individual commits. Coordinate edits to shared files and append prediction entries in separate commits before experiments. Use genuine completed work for the commit history. This schedule targets 21 descriptive commits over seven days, against the course minimum of 15 commits spread over at least five different days.
